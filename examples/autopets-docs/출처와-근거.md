첫 장은 공개 지침을 바탕으로 새로 요약한 설명입니다. 요구의 필요성 확인, 기존 코드·표준 라이브러리·플랫폼 기능·설치된 의존성 검토, 불필요한 추상화 축소를 다룹니다. 검증·데이터 손실 방지·보안·접근성까지 없애자는 의미는 아닙니다. resolve(...) 부분은 이 흐름을 설명하는 의사 코드입니다.

공개 실험은 Claude Code 2.1.177 / Haiku 4.5와 FastAPI+React 저장소, 12개 기능 과제와 과제별 반복 실험을 사용했습니다. 저장소가 보고한 코드 변경·토큰·비용·시간 감소는 해당 실험 조건의 결과입니다. 발표에는 보편적인 절약률이나 AutoPets의 측정 결과처럼 숫자를 제시하지 않았습니다. 2장의 ‘토큰 사용 감소 사례’는 이 공개 실험을 뜻합니다. 작업과 모델에 따라 효과가 달라집니다.

Ponytail을 설치하거나 실행하지 않았습니다. 개발자 일러스트는 사용자가 제공한 배너의 캐릭터를 기반으로 이미지 생성 도구로 정리한 발표용 자산입니다.

## 펫의 확장 계획
16장의 작업 상태 뒤에 네 장면을 추가했습니다. 모두 구현 완료가 아닌 시각화·상호작용 계획입니다.

- MCP: 서비스 자체를 알아볼 수 있도록 Figma·GitHub 공식 로고를 펫의 연결 소품으로 표현합니다. 특정 펫에 도구를 고정한다는 뜻은 아니며 모든 펫에 장착하는 방향입니다.
- 모델과 추론 강도: 모델은 Luna·Sol·Astra의 몸 크기 차이로, 추론 강도는 같은 모델·동일한 크기의 고양이 위 3칸 집중 게이지로 구분합니다. Light는 1칸, Medium은 2칸, High는 3칸입니다. 실제 성능의 정량 비율이나 큰 모델·높은 강도가 항상 적합하다는 평가가 아닙니다.
- 하네스: 같은 종류의 펫을 프로젝트·관련 채팅·서브에이전트 관계로 연결합니다. 각 개체의 역할은 소품과 이름으로 구분합니다. 앞의 단일 채팅 계획·실행 시나리오는 그대로 같은 한 펫의 상태 변화입니다.
- 진화: 옷·소품으로 꾸미고 사용·스킬 개선에 따라 외형이 진화하는 게이미피케이션 방향입니다. 성능 개선은 별도 검증할 목표이며 사용량 자체가 모델을 자동 훈련하거나 성능을 보장한다는 의미가 아닙니다.

Figma 원본 로고: [공식 브랜드 자료](https://www.figma.com/using-the-figma-brand/). 해당 로고는 도구 식별을 위한 발표용 콘셉트에 사용하며 제휴나 실제 연동 완료를 뜻하지 않습니다.

## 모델 라우팅의 필요성 (13장)
- [RouteLLM 공식 저장소](https://github.com/lm-sys/RouteLLM)
- [LMSYS 연구 설명](https://www.lmsys.org/blog/2024-07-01-routellm/)
- [논문](https://arxiv.org/abs/2406.18665)

RouteLLM이 공개한 특정 실험에서는 MT-Bench에서 GPT-4 성능의 95%를 유지하면서 최대 85% 비용 절감 사례를 보고했습니다. GPT-4 Turbo와 Mixtral 8×7B 조합 및 해당 연구의 라우터 학습·평가 조건에 한정된 결과입니다. 여기서 95%는 평가 성능의 상대 수준이며 답변 정확도 95%라는 의미가 아닙니다.

발표 화면에 ‘외부 연구 · RouteLLM’, 모델 조합, 벤치마크, 2024 공개 실험을 함께 표시했습니다. Jev나 AutoPets의 실험 결과 또는 어떤 모델 조합에서도 가능한 보장치로 옮기지 않습니다. 마지막 단계의 Astra → Luna는 별개의 AutoPets 설정 조합 예시입니다.

확인된 로컬 집계가 없는 모델 변경 횟수, 불만 건수, 평균 절약률은 만들지 않았습니다. 자체 벤치마킹은 17장의 제작 진행으로 분리했습니다.

# 발표 지시 수집 검수

정리일은 2026년 9월 30일이다. 이 작업은 대화에서 확인되는 지시를 재사용 가능한 문서와 데이터로 정리한 것이며, 발표를 다시 구현하거나 과거 성능 수치를 검증한 작업이 아니다.

## 수집 범위

- 현재 대화의 직접 요청·사용자 승인 계획과 기존 25건 사례집을 대조했다.
- 반복 메시지는 합쳐 36개 출처 묶음으로 남겼다. 원문 발췌와 정리 메모를 구분했다.
- 12개 분류, 64개 지침, 16개 복사용 프롬프트, 10개 수정 관계를 작성했다.
- 기존 change-01부터 change-25까지 모두 새 지침에서 연결되는지 확인했다.
- 9월 28일의 Figma 블록 이동과 UI 디자이너 구르미 수정은 최근 로컬 발표의 사례로 기록했다. 기존 v2.0.0 보관본의 모습이라고 표시하지 않았다.
- 다른 챗 전체·별도 실행 로그·첨부 이미지 전체 전사를 추가로 조사했다고 주장하지 않는다. 현재 문서는 대화에 나타난 제작 지시의 구조화 자료다.

## 내용 점검

- 직접 요청, 사용자가 구현을 요청한 계획, 사용자가 전달한 발표 지침을 출처 유형으로 구분했다.
- 자동 생성된 재사용 문장을 사용자 원문으로 표시하지 않았다. 원문은 전체 메시지의 전사가 아닌 발췌다.
- 문구 최소화와 의도적인 고밀도 기술 장면을 일반 원칙과 예외로 연결했다.
- 메모 제거·모델과 추론 구분은 대체, 새 사진과 Figma 소품 추가는 보완으로 구분했다.
- 흰 배경·초록색·5분·20장·구르미·15MiB·사진 설정값을 모든 발표의 필수 조건으로 만들지 않았다.
- 스타와 설치 수를 사용률로 바꾸지 않고, 제품의 효과·진행 상황·개인 관점을 사실로 확대하지 않도록 적용 범위를 명시했다.

## 수행한 기능 검수

| 검사 | 결과 |
| --- | --- |
| 지침 ID 중복과 출처 연결 | 64개 ID 고유, 참조된 출처 모두 존재 |
| 수정 관계의 출처 연결 | 10개 관계의 출처 모두 존재 |
| 기존 25건 사례의 연결 | 모두 연결됨 |
| HTML에 포함된 데이터 | JSON 원본과 동일 |
| JavaScript 문법 | 구문 검사 통과 |
| 문서 내부 상대 링크 | 대상 파일 존재 확인 |
| 검색 | 세부 문구 검색 결과에 해당 지침 표시 |
| 분류 필터 | 이미지와 로고의 6개 지침 표시 |
| 상세 모달 | 원문 발췌와 일반화한 문장 구분 표시 |
| 복사 | 복사 버튼 실행 후 성공 상태 확인 |
| 통합 프롬프트 | 새 발표 시작 문장 표시 확인 |
| 수정 관계 탭 | 10개 관계 표시 확인 |
| 화면 | 브라우저에서 읽기와 배치 확인, 미리보기 저장 |
| 스킬 연결 | 저장소와 설치된 스킬에 같은 선택형 참고 경로 추가 |

검색·필터·모달·복사는 로컬 HTTP에서 확인했다. 검색 페이지의 CSS·JavaScript·데이터는 모두 HTML 안에 있으며 필수 외부 자산은 없다. 브라우저 도구의 URL 정책이 file 프로토콜 접근을 차단했으므로 파일 직접 열기를 실제 통과했다고 기록하지 않았다. 클립보드가 허용되지 않는 경우 텍스트 선택으로 전환하는 경로는 코드에 포함했지만 브라우저 권한을 강제로 바꿔 시험하지 않았다.

스킬의 기존 YAML은 수정하지 않았으며 필수 필드와 새 참고 링크를 별도로 확인했다. 표준 quick_validate 도구는 현재 Python에 PyYAML이 없어 실행되지 않았다. 이를 표준 검사 통과로 기록하지 않는다.

## 수집 단계의 파일과 범위

검색 페이지는 약 84.4KiB이며 사진·로고·애니메이션 자산을 복제하지 않았다. 전체 원문과 지침은 필요할 때만 읽는 참고 자료로 분리했다. 실제 토큰 사용량이나 절감률은 측정하지 않았다.

자료 수집을 완료한 시점에는 현재 발표 HTML, 기존 세 보관본, v2.0.0 릴리스, 공개 갤러리를 수정·재배포하지 않았다. 저장소의 로컬 문서·데이터·생성 도구와 설치된 개인 스킬의 참고 경로만 갱신했다.

## 후속 GitHub 반영

이후 사용자의 GitHub 추가·보완 요청으로 메인 갤러리에 라이브러리 링크와 자료 ZIP을 연결하고, 정적 배포 목록·패키지 목록·구조화 데이터 검사를 보완한다. 기존 발표 보관본과 v2.0.0 릴리스는 유지한다. 배포 성공 여부는 해당 커밋의 GitHub Actions 결과를 기준으로 확인한다.

# 발표 출시 검수

## 검수 범위 결정
변경한 장면·단계·공통 파일을 기록한다. 원본 보관본은 해시로 보호한다. 전체 출시에서는 모든 페이지와 내부 단계를 1280×720, 1920×1080에서 캡처한다. 자동 geometry 검사는 화면 밖 요소를 찾는 보조 수단이며 의도적인 겹침·여백·가독성은 이미지를 보고 판단한다.

## 내용과 시각
- 요청 원문과 반영된 화면을 연결한다. 최신 정정이 이전 해석을 대체했는지 검사한다.
- 사례·팀 가설·실험 결과·확장 계획을 구분한다. 숫자는 단위·조건·출처·날짜를 확인한다.
- 제목·본문의 잘림, 원치 않는 겹침, 로고 비율, 픽셀 경계, 사진의 얼굴, 집중 게이지를 확인한다.
- 주요 UI는 이미지가 가리지 않아야 한다. 같은 캐릭터의 상태 변화와 여러 작업자의 분화를 혼동하지 않는다.
- 원본 사진 4장 등 사용자가 지정한 자산의 누락을 점검한다.

## 조작
- 빈 곳, 글자, 이미지, 펫을 눌러 동일하게 한 단계 진행하는지 확인한다.
- 연출 중 중복 다음 입력은 추가 진행시키지 않는다. 이전 입력은 연출 타이머를 취소한다.
- URL로 모든 단계 직접 진입, 이전 장 마지막 단계 이동, 끝에서 멈춤, 목차·처음·마지막 이동을 확인한다.
- 모션 줄이기에서 정보와 최종 추천을 볼 수 있어야 한다. 자동으로 전체 발표를 넘기지 않는다.
- 선택 내보내기: 각각의 단일 장면, 재정렬한 여러 장면, 마지막 3장 묶음, 그 묶음 뒤에 추가 장면이 있는 순서를 검사한다.
- 키보드 조작과 팝업 닫기, 포커스 표시, 모바일 갤러리 레이아웃을 확인한다.

## 독립 실행과 패키지
- 최종 HTML을 새 폴더에 두고 외부 네트워크를 차단한 브라우저에서 연다. 필수 자산은 data URI/인라인 코드여야 한다.
- URL 문자열을 모두 금지하지 않는다. SVG namespace·출처 링크와 실제 네트워크 요청을 구분한다. localhost·개인 파일 경로를 검사한다.
- ZIP을 별도 폴더에 풀고 node build.mjs로 재빌드한다. 포함된 presentation.html과 해시를 비교한다.
- 실제 확장자와 이미지 magic bytes, SVG 문법을 검사한다. HTML 오류 페이지를 이미지로 저장한 파일을 탐지한다.
- 임시 파일, node_modules, 비밀키·실행 로그, 참조하지 않는 고해상도 원본, 최신 패키지의 오래된 대본을 제외한다. 옛 보관본의 내용은 바꾸지 않는다.
- 운영체제별 시스템 폰트는 다를 수 있다. 현재 템플릿은 로컬 설치 폰트 체계를 사용하므로 없는 폰트 환경에서도 넘침을 검사한다. 모든 PC에서 동일한 글꼴이라고 주장하지 않는다.

## 용량
- 바이트와 MiB를 함께 기록한다(1MiB = 1,048,576바이트). HTML, ZIP, 이미지별 크기·해상도·형식, 반복 삽입량을 보고한다.
- 이 사례 규모에서는 독립 HTML 목표 15MiB, 조사 기준 20MiB. 초과하면 큰 자산과 사유를 보고하고 내용을 자동 삭제하지 않는다.
- 사진: WebP 품질 90, 최대 1350×1800을 이번 사례의 출발점으로 사용했다. 다른 화면에서의 적정 해상도는 표시 크기와 확대 요구로 정한다.
- 픽셀/로고/텍스트 이미지는 원본 또는 무손실을 우선한다. 사진과 동일한 손실 압축 정책을 강제하지 않는다.
- 사진 압축만 요청되면 JS/CSS와 사진 외 자산의 해시를 비교한다. 그림의 품질과 애니메이션 실행을 각각 확인한다.
- 원본 보관 위치와 최적화 사본의 매핑을 남긴다. 배포에는 필요한 사본만 포함한다.

## 결과 보고
통과, 실패, 자동 검사 한계, 수동 확인 결과를 구분한다. 실행하지 않은 검사를 통과로 적지 않는다. Playwright Chromium 검수는 Windows/macOS의 모든 브라우저 실기 검수를 뜻하지 않는다. PDF를 요구받은 경우에만 V1 fidelity export와 역렌더 검수를 추가한다.

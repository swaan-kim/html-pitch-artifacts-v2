# Content Architecture

Use this only for new decks, one-pagers, or major narrative rewrites.

## Communication job

Write one internal sentence before choosing pages:

> By the end, **[audience]** should **[understand, believe, approve, or do]** because **[central takeaway]**.

Each page then gets one contract:

- stable page ID;
- one audience-facing claim;
- one primary proof or visual;
- the conclusion the audience should draw;
- source information for non-trivial claims.

## Reusable narrative routes

Choose the smallest route that fits the job.

- Pitch: problem -> failed status quo -> product -> proof -> market -> business model -> execution -> ask.
- Technical: system need -> constraints -> architecture -> critical flows -> validation -> limitations -> next action.
- Decision: question -> criteria -> options -> evidence -> recommendation -> consequence.
- One-page IR: problem number -> product/UI number -> market or growth number -> execution proof.

Do not treat an agenda as a narrative. Every section must create the need for the next.

## Density

- One primary claim per page.
- One dominant visual composition, not a grid of unrelated cards.
- Shorten copy or change layout before shrinking type.
- Let statistics express a conclusion; do not present a pile of unframed numbers.

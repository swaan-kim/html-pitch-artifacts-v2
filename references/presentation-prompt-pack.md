# 상황별 발표 제작 프롬프트

대괄호를 내 발표에 맞게 바꾸고 필요한 문단만 복사한다. 이 문장들은 사용자 원문이 아니라 누적 요청에서 일반화한 재사용 문장이다. 현재 요청이 이 예시와 다르면 현재 요청이 우선한다.

## 새 발표 시작

```text
[주제]를 [청중]에게 [시간]분 동안 발표할 HTML PPT를 만들어줘.
발표가 끝나면 무엇을 만드는지와 왜 그렇게 결정했는지를 이해해야 해. 먼저 최신 자료와 목표를 확인하고 목차·시간 배분을 잡아줘.
이번에는 흰 배경과 여백, 실제 브랜드 로고·이미지 중심으로 가자. 화면에는 핵심 문장과 필요한 라벨만 남기고 내가 말할 세부 설명, 클릭 안내, 메모·전체화면 UI는 빼줘.
한 번 클릭하면 연출하고 멈춘 뒤 다음 클릭에 이어지게 해줘. 앞뒤 장면의 같은 요소는 이어서 이동시키고, 복잡함을 체감시키는 장면 뒤에는 같은 내용을 쉽고 직관적으로 보여줘.
조사·가설·콘셉트·검증 결과는 구분하고 수치를 만들지 마. [반드시 포함할 자료]를 빠뜨리지 말아줘.
마지막에는 다른 컴퓨터에서 오프라인으로 열리는 독립 HTML과 요청한 편집 자료를 만들고, 가독성·클릭·이전 이동·모션 줄이기·자산 누락·용량을 검수해줘. [수정 범위/기존 자료 유지 조건]도 지켜줘.
```

## 최소한의 수정 요청

```text
[장면]에서 [문제]가 있어. [바꿀 모습]으로 수정해줘. [앞뒤 요소]가 이어지게 하고 [유지할 사항]은 그대로 둬. 이번에는 [PPT/문구/이미지]만 수정하고 [확인할 항목]을 검수해줘.
```

## 문구와 조작 안내 줄이기

```text
세부 문구는 어지간하면 삭제해줘. 내가 말할 내용은 화면에 다시 쓰지 말고, 제목 한 문장·꼭 필요한 라벨·이미지와 로고만 남겨줘. 하단 클릭 안내, 메모, 전체화면, 연출 중 같은 문구도 숨겨줘. 의미 구분에 필요한 상태·단위·짧은 추천 이유는 유지해줘.
```

## 로고 플레이

```text
[서비스들]의 실제 로고로 설명해줘. 단순히 나열하지 말고 [모임/연결/확장/선택/도구로 전환]이 보이게 해줘. 로고 비율과 색을 유지하고, 긴 문구는 줄여줘.
```

## 어려운 기술에서 쉬운 상징으로

```text
앞 장면은 [실제 기술 용어·설정]을 정확하지만 일부러 복잡하게 보여줘. 다음 장면에서는 같은 뜻을 [캐릭터/이미지]와 짧은 결과 설명으로 풀어줘. 어려움→쉬움이 전환 자체로 느껴져야 해. 가짜 용어·확인 안 된 효과 수치는 넣지 마.
```

## 객체를 다음 장면으로 가져오기

```text
앞 장면의 [로고/블록] 하나를 그대로 가져와 다음 장면에서 [캐릭터]의 [도구/소품]이 되게 해줘. 이동과 크기 변화가 연결돼 보이게 하고, 추가 클릭 단계 없이 기존 흐름 안에서 끝내줘. 이전 이동과 모션 줄이기에서도 제자리에 보여야 해.
```

## 캐릭터로 직무 표현

```text
[캐릭터] 자체가 [직무]처럼 보였으면 해. 얼굴·색·비율은 유지하고 [복장]·[도구]·[작업 자세]를 더해줘. 이름 라벨만 붙이지 말고, 캐릭터가 도구를 사용하는 모습이 읽히게 해줘. 얼굴과 주 작업 화면은 가리지 마.
```

## 원본 인터뷰 이미지 분류

```text
이 메모 이미지를 [문제 원인]별로 잘 분류해서 보여줘. 내가 위주로 읽고 설명할 테니 긴 요약을 옆에 또 쓰지 마. 원본과 요약, 실제 사례와 팀 가설을 구분하고 실명·직접 인용 표기는 자료에 맞춰 처리해줘.
```

## 비교가 헷갈릴 때

```text
[A]와 [B]가 지금 똑같아 보여서 구분이 안 돼. A는 [크기], B는 [같은 크기 안의 게이지]처럼 서로 다른 시각 변수로 나눠줘. 비교하지 않는 요소는 고정하고 라벨과 표시가 정확히 대응하게 해줘.
```

## 발표용 순차 인터랙션

```text
하나하나 버튼을 누를 시간이 없어. 빈 곳·텍스트·이미지·캐릭터 어디를 눌러도 같은 순서로 진행되게 해줘. 한 번 클릭하면 짧은 연출을 끝내고 멈춰줘. 연출 중 중복 다음 입력은 막고 이전 이동은 즉시 취소·복구해줘. 키보드와 모션 줄이기도 확인해줘.
```

## 기술 아키텍처 한 장

```text
[사용자 요청] → [사용자에게 보이는 인터페이스] → [프롬프트/라우팅/스킬/도구] 관계를 한 장에 그려줘. 실제 로고와 짧은 라벨을 중심으로 하고, 현재 가능한 것과 구현 계획을 구분해줘. 앞 장의 필요성 설명과 자연스럽게 이어줘.
```

## 여러 장을 원페이지처럼

```text
[좌측 관점]과 [우측 관점]이 [변화]를 거쳐 [우리의 역할]로 연결되는 흐름이야. 필요하면 두세 장으로 나눠도 되지만 로고·텍스트가 같은 화면 위에서 이동하는 것처럼 이어줘. 이 장면은 타원 영역 대신 직선과 타이포그래피의 이동·확장으로 표현해줘.
```

## 증거와 효율 수치

```text
[기능]의 필요성을 보여줄 근거를 찾아 한 장에 넣어줘. 실제 없는 변경 횟수·불만 수·절약률은 만들지 마. 확인된 지표의 단위·출처·날짜·조건을 표시하고, 외부 실험을 우리 제품의 검증 결과로 바꾸지 마.
```

## 사진과 팀명 보완

```text
첨부한 [N]장 모두 포함해줘. [강조할 사진]은 크게 보여주고 기존 사진은 보조로 유지해줘. [정확한 팀명]을 짧게 넣고, 사진에서 캐릭터로 이어지는 연결을 살려줘. 누락·왜곡·얼굴 가림을 확인해줘.
```

## 용량과 최종 패키지 검수

```text
다른 PC에서 인터넷 없이 발표할 수 있게 독립 HTML로 만들어줘. 큰 사진부터 표시 크기에 맞게 최적화하고 원본은 보존해줘. 픽셀·로고·글자는 일괄 손실 압축하지 마.
HTML·ZIP·이미지별 크기/해상도/형식, 중복 삽입량과 전후 차이를 보고해줘. 목표 [MiB]를 넘으면 이유를 설명하고 내용을 임의로 빼지 마.
화면 잘림·겹침·자산 누락·내부 단계·중복 클릭·이전 이동·모션 줄이기·오프라인을 확인해줘. 편집 ZIP은 새 폴더에서 재빌드하고, 압축만 했다면 JS/CSS와 다른 자산 해시도 비교해줘.
```

## 버전과 수정 기록을 남기기

```text
초기본과 최종본을 원본 그대로 따로 보관하고 해시로 확인해줘. 수정은 내 요청 원문→의도→이전/이후 화면→반영 장면→재사용 프롬프트→확인 기준으로 기록해줘. 과거 화면이 없으면 없다고 표시하고, 최신 정정이 이전 요청의 대체인지 보완인지도 남겨줘. 전체 기록을 매번 읽지 않아도 필요한 항목만 찾을 수 있게 해줘.
```

## 최소 사용 순서

1. 새 발표 시작 프롬프트에 목적·시간·청중·자료를 채운다.
2. 표현을 고를 때 로고·전환·캐릭터 등 필요한 프롬프트만 추가한다.
3. 수정은 대상과 유지할 범위를 정해서 요청한다.
4. 최종 납품 때만 용량·오프라인·패키지 전체 검수를 적용한다.

# 적은 읽기로 같은 품질 유지하기

1. 먼저 장면 목록과 파일 크기·해시를 읽는다. 작은 문구 수정이면 해당 HTML 조각과 관련 CSS 규칙만 읽는다.
2. 이미 확인한 원문·출처·이미지는 재검색하지 않는다. 바뀌는 수치의 최신화가 요청된 경우에만 새로 검증한다. 옛 발표의 수치 스냅샷은 확인일을 유지한다.
3. 이미지 파일, gallery/payload.js, 보관 HTML의 Base64를 모델 출력에 넣지 않는다. 이미지 메타데이터나 필요한 화면 캡처를 사용한다.
4. 한 장 수정 → 해당 장면/내부 단계 검수. 런타임·공통 스타일 수정 → 전체 동작·영향 화면 검수. 통과한 검사를 변경 없이 반복하지 않는다.
5. 원본을 매번 전체 재작성하지 않는다. 반복적인 장면 조합·내보내기·용량 집계는 스크립트로 처리한다.

## 비교 방법
문구 수정, 한 장 추가, 사진 교체, 장면 재조합 네 작업에 대해 처음부터 전체 파일을 읽는 방식과 장면 목록+대상 파일만 읽는 방식의 입력 바이트를 비교한다. `reports/context-scope.json`은 동일한 소스에 대한 읽기 범위 비교이며 모델을 실행한 토큰 청구 측정이 아니다. 이미지 토큰, 캐시, 도구 비용, 추론 토큰은 포함하지 않는다. 실제 토큰 사용 기록이 있으면 별도 필드로 표시한다.

SKILL.md는 공유 판단에 필요한 최소 지침만 유지한다. 특정 프로젝트에서 생긴 수정은 casebook에 추가하고, 여러 과제에서 반복된 오류만 핵심 규칙으로 승격한다. 품질 확인을 없애는 것을 토큰 절감으로 삼지 않는다.
